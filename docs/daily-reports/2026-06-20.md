## Important Decisions

- Caddy is managed as one VPS-wide shared stack, not per application.
- Application containers join `edge` only when they need to be reachable by
  Caddy.
- Database containers stay off `edge`.
- `suite-stg` and future `suite-demo` should use separate environment roots,
  because demo is user-facing and should be treated as production-like.
- The VPS no longer needs a sibling `NENE2` clone for Suite staging. The Suite
  Docker image clones NENE2 during image build.
- The deploy logic is repository-managed (`ops/staging/deploy-staging.sh`,
  build + health only), with VPS-specific values left outside git
  (`APP_DIR` / `HEALTH_URL` overridable). The GitHub Actions SSH step performs
  the `git fetch` / `git reset --hard origin/main` so the script never overwrites
  itself and there is no first-run bootstrap gap.

## Current Runtime Layout

- The shared reverse proxy and each environment root live in **out-of-repo paths on
  the host**; environment secret files (`.env.suite`) are **host-local, not
  committed**.
- The deploy script is **repository-managed** (`ops/staging/deploy-staging.sh`,
  build + health only). The old host-local deploy script is retired.
- Request path: internet → shared reverse proxy (80/443) → edge network → app
  container. The database sits on the app's default network, off the edge.

## Important Decisions

- The reverse proxy is managed as **one VPS-wide shared stack**, not per app.
- Application containers join the edge network **only** when they need to be
  reachable by the proxy; database containers stay off it.
- `suite-stg` and a future `suite-demo` should use **separate environment roots**,
  because demo is user-facing and should be treated as production-like.
- The host no longer needs a sibling `NENE2` clone for Suite staging — the Suite
  Docker image clones NENE2 during image build.
- Deploy logic is repository-managed (build + health only), with host-specific
  values left **outside git** (`APP_DIR` / `HEALTH_URL` overridable). The CI SSH
  step performs the `git fetch` / `git reset --hard origin/main`, so the script
  never overwrites itself and there is no first-run bootstrap gap.

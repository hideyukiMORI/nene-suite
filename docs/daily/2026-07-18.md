## D1 是正: GuardedJwtSecretResolver 載せ替え（#390 / PR #391 → merge fb04f14）

- 発端は hub の確認依頼「suite はフリート標準の Guarded 形に乗っているか」。照合の結果
  **乗っていない**を実測で確認: ローカル実装は fail-closed＋strict opt-in を持つが、Guarded 形の
  「**Production では opt-in を無視して必ず throw**」の段が欠落（本番で
  `NENE_SUITE_ALLOW_DEV_SECRET=1` を誤設定すると dev secret 署名が通り得た）。
- `JwtSecretResolver` を `Nene2\Auth\GuardedJwtSecretResolver` への thin adapter 化
  （suite の env 名と strict opt-in 綴りは維持・dev secret は `devSecret:` スロット注入＝
  D1 guarded-literal exemption と同型）。`RuntimeServiceProvider` から `AppConfig->environment`
  （`APP_ENV` 由来）を注入。テスト+7（production ハードフェイル実証を含む）。
- baseline から D1 を shrink（33→32 entries・初の shrink）。
- 申し送り: **`APP_ENV=production` が実機 env に無いと防御段は眠る**（configured secret がある限り
  安全側）。hub がフリート横断の post-launch ops 台帳「全製品の APP_ENV 棚卸し」に昇格登録〔伝聞〕。

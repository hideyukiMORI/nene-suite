# Internationalization (i18n)

**Status: binding (Phase 1+ frontend).** NeNe Suite is a **locale-switching service**:
every user-visible string in the apex shell and installer wizard **MUST** come from
typed message catalogs — never hardcoded in components.

Reference implementation: nene-records `frontend/src/shared/i18n/`.

**Related:** [`frontend-standards.md`](./frontend-standards.md), ADR 0009,
[`../explanation/installer-disclaimer-copy.md`](../explanation/installer-disclaimer-copy.md).

---

## Principles

| Principle | Meaning |
| --- | --- |
| **Catalog SSOT** | `messages/en.ts` defines every `MessageKey`; other locales are `Partial<MessageCatalog>` |
| **Type-safe keys** | `t('suite.install.disclaimer.title')` — keys are compile-time checked |
| **English fallback** | Missing translation → English string at runtime |
| **No UI literals** | JSX/TSX must not contain user-facing prose (except dev-only debug) |
| **API vs UI** | OpenAPI / Problem Details titles stay **English**; UI maps errors via `mapProblemDetailsToMessageKey` |
| **Smooth switch** | Locale change updates `document.documentElement.lang`, font stack, and all `t()` output without reload |

## Supported locales

Same six locales as NENE2 docs / nene-records:

| ID | Label |
| --- | --- |
| `en` | English (default, source catalog) |
| `ja` | 日本語 |
| `fr` | Français |
| `zh-Hans` | 中文（简体） |
| `pt-BR` | Português (Brasil) |
| `de` | Deutsch |

Defined in `frontend/src/shared/i18n/locales.ts`.

### Locale pickers and the toggle clamp

Two pickers exist, with distinct contracts:

- **`LocaleSwitcher`** (settings → General → Language) — the full six-locale
  `<select>`. This is the only place every locale is reachable, including the
  four English-fallback stubs. Any locale can be entered and left here.
- **`LocaleToggle`** (header) — a compact shortcut for the **maintained pair
  (`en` + `ja`) only**. Clamp rule: from `ja` it switches to `en`; from `en`
  it switches to `ja`; from any other locale it clamps to `en` (the fallback
  language that user is already reading) — it must **never** move a non-`ja`
  user to `ja` implicitly. Returning to a stub locale is done via
  `LocaleSwitcher`.

`resolveLocale` maps BCP 47 tags onto the six IDs (exact → two-part prefix →
one-part prefix → alias table → `en`). Simplified-Chinese region tags
(`zh-CN`, `zh-SG`, bare `zh`) alias to `zh-Hans`; everything unknown falls back
to `en`.

## Module layout (mandatory)

```text
frontend/src/shared/i18n/
  index.ts                 # public exports
  locales.ts               # SupportedLocale, resolveLocale
  translate.ts             # translate(), MessageKey, MessageParams
  i18n-context-ref.ts      # I18nContext (no JSX — fast refresh)
  i18n-context.tsx         # I18nProvider
  use-translation.ts       # useTranslation()
  map-problem-details.ts   # HTTP status → MessageKey
  locale-fonts.ts          # per-locale font stacks
  test-helpers.tsx         # renderWithI18n, withI18n
  messages/
    en.ts                  # MessageCatalog — ALL keys (required)
    ja.ts                  # full coverage required before release
    fr.ts                  # Partial — fallback to en
    zh-Hans.ts
    pt-BR.ts
    de.ts
    index.ts               # getMessages(locale)
```

**Forbidden:** message strings in `features/*/ui`, `pages/`, or root `src/locales.json` without ADR.

## Message key naming

Pattern: `{scope}.{feature}.{element}`

| Prefix | Usage |
| --- | --- |
| `common.actions.*` | Save, cancel, retry, … |
| `common.error.*` | Generic HTTP / unknown errors |
| `common.dialog.*` | Shared dialog chrome |
| `common.state.*` | Loading, empty, error labels |
| `suite.nav.*` | Apex navigation |
| `suite.locale.*` | Language selector |
| `suite.auth.*` | Apex login |
| `suite.launcher.*` | Installed app grid / SSOT hints |
| `suite.install.*` | Installer wizard (steps, actions, errors) |
| `suite.disclaimer.*` | Disclaimer screens (content from installer-disclaimer-copy) |
| `suite.audit.*` | Audit export UI (Phase 2+) |

Register new prefixes in [`naming-conventions.md`](./naming-conventions.md) before use.

### Interpolation

Use `{{paramName}}` in catalog strings:

```typescript
t('suite.install.apps.selectedCount', { count: 3 })
// en: "{{count}} app(s) selected"
```

## Runtime usage

### Provider (app root)

```tsx
// app/providers.tsx
import { I18nProvider } from '@/shared/i18n'

export function AppProviders({ children }: { children: React.ReactNode }) {
  return <I18nProvider>{children}</I18nProvider>
}
```

### Components

```tsx
import { useTranslation } from '@/shared/i18n'

export function InstallDisclaimerStep() {
  const { t } = useTranslation()
  return <p>{t('suite.disclaimer.shortNotice')}</p>
}
```

### Locale persistence

- Storage key: **`nene-suite-locale`** (localStorage)
- Detection order: storage → `navigator.language` → `en`
- Locale selector in apex shell header (`suite.locale.select`)

## Adding or changing copy

1. Add key to **`messages/en.ts`** first.
2. Add Japanese to **`messages/ja.ts`** in the same PR (required for UI PRs).
3. Optionally update `fr`, `zh-Hans`, `pt-BR`, `de` (Partial OK).
4. Use `t('key')` in component — remove any hardcoded string.
5. Run `npm run test --prefix frontend` — `i18n key coverage` must pass.

Disclaimer / compliance copy: sync meaning with
[`installer-disclaimer-copy.md`](../explanation/installer-disclaimer-copy.md);
**English canonical text in `en.ts`**, Japanese operator text in `ja.ts`.
